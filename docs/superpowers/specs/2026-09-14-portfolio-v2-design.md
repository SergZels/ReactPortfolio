# Портфоліо v2 — дизайн

Дата: 2026-09-14
Гілка: `v2` (від `main`, репозиторій `SergZels/ReactPortfolio`)
Статус: затверджено до реалізації

## Мета

Замінити портфоліо на CRA сучасним сайтом, який:

- не залежить від доступності домашнього сервера `zelse.asuscomm.com`;
- дозволяє додати проєкт зміною в одному файлі, а не в чотирьох;
- працює двома мовами (українська / англійська);
- лишається статичним SPA на GitHub Pages.

Візуальний напрям — **інженерний**: моношрифт у технічних деталях, щільна
сітка, факти й цифри на видному місці. Обрано з трьох показаних варіантів.

## Модель даних

Увесь контент проєктів — в одному типізованому файлі `src/data/projects.ts`.

```ts
type Localized = { uk: string; en: string };

type ProjectStatus = 'production' | 'archived' | 'pet';

type Project = {
  slug: string;                  // 'rrepair-crm' — частина URL
  title: string;                 // назва як є, не перекладається
  year: number;                  // для сортування й таймлайну
  status: ProjectStatus;
  featured: boolean;             // потрапляє у великі картки на головній
  summary: Localized;            // 1–2 речення під заголовком
  stack: string[];               // ['django', 'postgres', 'docker']
  links: {
    github?: string;
    telegram?: string;
    live?: string;
    youtube?: string;
  };
  cover: string;                 // шлях до обкладинки
  shots: { src: string; caption: Localized }[];
};
```

`Localized` робить пропущений переклад помилкою компіляції, а не порожнім
місцем на сайті.

Один шаблон `src/routes/Project.tsx` рендерить будь-який кейс за slug. Додавання
проєкту = один об'єкт у масиві.

### Slug-и та старі URL

Старі маршрути (`/RR`, `/Dedit`, `/Project1`, …) стають `/project/{slug}`.
Щоб зовнішні посилання не побилися, `src/routes/redirects.ts` містить таблицю
`старий шлях → новий slug`, і роутер віддає на них `<Navigate replace>`.

## Двомовність

Без `i18next` — для цього обсягу вистачає власного контексту:

- `src/i18n/LangContext.tsx` — провайдер і хук `useLang()`;
- `src/i18n/ui.ts` — словник інтерфейсу, тип `Record<UiKey, Localized>`;
- контент проєктів уже двомовний усередині моделі даних.

Початкова мова — з `navigator.language` (українська, якщо префікс `uk`, інакше
англійська), вибір зберігається в `localStorage` під ключем `portfolio-lang`.
Перемикач — у шапці.

**Обсяг ручної роботи: 47 підписів до скриншотів + короткі описи 24 проєктів +
текст «про себе» + 6 записів таймлайну.** Усе це зараз лише англійською.
Українські версії пише Claude, але їх **обов'язково вичитує Сергій** — це його
голос і його проєкти, автоматичний переклад тут не годиться.

## Зображення

Скрипт `scripts/optimize-images.mjs` (запускається вручну, не на кожній збірці):

- вхід — `Content/**/*.{png,jpg,jpeg}`;
- вихід — `public/shots/{slug}/{n}-{640,1280}.webp`;
- якість 80, без збільшення менших за цільову ширину;
- у шаблоні — `srcSet` з двох ширин + `loading="lazy"` + явні `width`/`height`,
  щоб не стрибав layout.

Очікуваний результат: 103 МБ → орієнтовно 10–15 МБ. Точну цифру перевіряємо
після першого прогону; якщо вийде більше 25 МБ, зменшуємо більшу ширину до 1024.

Після цього жодного посилання на `zelse.asuscomm.com` у коді не лишається.

## Структура сайту

Головна `/` — одна сторінка зі скролом:

1. **Hero** — ім'я, рядок спеціалізації моношрифтом, три метрики
   (років у коді / проєктів / технологій у стеку), кнопки «Кейси» і «CV».
2. **Про себе** — текст із поточного `dataabout` + таймлайн 1999 → 2024
   з `worktimeline` (6 записів).
3. **Стек** — 18 технологій.
4. **Кейси** — 6 featured великими картками, решта 18 компактною сіткою
   з фільтром за технологією.
5. **Контакти** — email, Telegram, GitHub, LinkedIn, YouTube прямими кнопками.

Сторінка кейсу `/project/{slug}`: назва, статус, рік, стек, посилання, далі
скриншоти з підписами. Кнопка «назад до кейсів».

`*` → сторінка 404 з посиланням на головну (зараз невідомий шлях мовчки віддає
головну, що плутає і шкодить індексації).

## Тема оформлення

Одна темна тема, зроблена добре. Перемикача світла/темна немає: варіант C
побудований навколо темного тла, а підтримка двох тем подвоює роботу з
контрастами заради функції, якою на портфоліо користуються рідко.

Якщо тема знадобиться пізніше — кольори задаються CSS-змінними на `:root`,
тож додати світлий набір буде окремою невеликою задачею, а не переробкою.

## Анімації

CSS + `IntersectionObserver`, без бібліотек:

- поява секцій при скролі (`opacity` + `translateY`, 300 мс);
- hover-стани карток (`border-color`, `transform: translateY(-2px)`);
- фокус-кільця на всіх інтерактивних елементах.

Усе всередині `@media (prefers-reduced-motion: no-preference)` — для тих, хто
вимкнув анімації в системі, сайт статичний.

Прибираються: typewriter у hero, анімовані кільця на кнопках, кастомний курсор
(на тачскрінах він марний, а на десктопі заважає).

## Тести

Vitest + Testing Library. Тестуємо те, що реально ламається при додаванні
контенту:

**Цілісність даних** (`src/data/projects.test.ts`):
- усі slug унікальні й відповідають `^[a-z0-9-]+$`;
- кожен `summary` і `caption` має непорожні `uk` і `en`;
- рівно 6 проєктів з `featured: true`;
- файли `cover` і всіх `shots` існують на диску;
- усі значення `stack` — з відомого списку технологій (захист від друкарських
  помилок, які ламають фільтр).

**Словник** (`src/i18n/ui.test.ts`):
- кожен ключ має `uk` і `en`;
- немає ключів, яких не використовує жоден компонент.

**Поведінка**:
- фільтр за технологією показує саме ті проєкти, у яких вона є;
- `/project/{slug}` рендерить назву й усі скриншоти;
- невідомий slug дає 404, а не головну;
- старий URL зі списку редиректів веде на новий.

Візуальна перевірка — через Playwright: скриншоти головної й однієї сторінки
кейсу на десктопі (1280) та мобільному (390), обома мовами.

## Деплой

GitHub Pages, як зараз. Одна деталь потребує уточнення перед налаштуванням:
репозиторій називається `ReactPortfolio`, а `package.json` містить
`homepage: "/PortfolioReact"` — ці значення не збігаються. Перед деплоєм треба
з'ясувати, за якою адресою сайт має відкриватися, і виставити `base` у
`vite.config.ts` відповідно.

Оскільки це SPA на GH Pages, зберігається наявний прийом із копіюванням
`index.html` у `404.html` — інакше пряме відкриття `/project/{slug}` дасть
помилку 404 від сервера.

## Чого свідомо не робимо

- **SSR / Next.js** — для статичного портфоліо на GH Pages не окупається.
- **CMS** — контент змінюється кілька разів на рік, файл у git зручніший.
- **Блог** — окремий проєкт, не змішуємо.
- **Аналітика** — не потрібна для цієї задачі; за потреби додається одним
  тегом пізніше.
- **Перемикач теми** — див. розділ «Тема оформлення».
